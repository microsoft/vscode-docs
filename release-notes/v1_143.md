## Agents

### Run Copilot models on your device (Experimental)

Laptops such as the new [Surface Laptop Ultra](https://www.microsoft.com/en-us/surface/devices/surface-laptop-ultra), powered by NVIDIA RTX Spark with up to 128 GB of unified memory, have enough GPU memory to run a capable coding model locally. On-device models let you use that hardware with Copilot: download MAI Code 1.1 Flash from the new **On This Device** tab in the model picker and chat with it in Copilot harness sessions, with model processing on your device. VS Code downloads and manages the model for you. Responses that run on your device are labeled **On-device** and don't use AI credits.

<video src="images/1_143/on-device-models.mp4" title="Video showing MAI Code 1.1 Flash downloaded from the On This Device tab in the model picker, loaded, and answering a chat prompt on the device." autoplay loop controls muted></video>

To get started, install a [llama.cpp build](https://github.com/ggml-org/llama.cpp/releases) that supports the model, set `setting(chat.copilot.localModel.llamaServerPath)` to its `llama-server` executable, and enable `setting(chat.copilot.localModel.enabled)`. On-device models require GitHub sign-in and an NVIDIA GPU with 96 GB or more of GPU memory. To let Auto route suitable requests to the on-device model with cloud fallback, turn on **Use in Auto** on the model's details page.

Learn more about [on-device models](https://code.visualstudio.com/docs/agent-customization/language-models#_use-on-device-models-experimental).

### Bring your own OpenAI model to Voice Mode (Preview)

Use your own OpenAI API key and live model for voice-driven coding conversations instead of the hosted Voice Mode backend. Add your OpenAI key in Models Management, enable `setting(agents.voice.enabled)`, and set `setting(agents.voice.useBYOKVoiceModel)` to a live model ID, like `gpt-live-1` that your key can access.

### Reclaim storage from inactive worktrees (Experimental)

Run **Chat: Open Worktree Cleanup** to see how much disk space inactive agent session worktrees use and remove the ones you no longer need. Filter sessions by how long they have been inactive, review each worktree's size, and select the worktrees to clean up.

The cleanup editor also lets you configure automatic cleanup for sessions with merged pull requests and control whether VS Code suggests cleanup when session storage grows large.

![Screenshot showing the worktree cleanup editor with cleanup settings and inactive session worktrees.](images/1_143/worktree-cleanup-editor.png)

When `setting(chat.agentSessions.sessionStorageCleanupSuggestion.enabled)` is enabled, the Agents window notifies you when enough inactive worktrees accumulate or they use enough disk space to make cleanup worthwhile.

![Screenshot showing a worktree cleanup suggestion in the Agents window.](images/1_141/worktree-cleanup.webp)

Cleaning up marks the selected sessions as done and deletes their worktrees. You can restore a session later to recreate its worktree. Active, running, needs-input, and pinned sessions are protected from cleanup.

## Editor Experience

### Diagnostic highlight limits

To improve diagnostic visibility in files with many reported problems, the editor highlight limit increases from 500 to 5,000 diagnostics per file.

A **Diagnostic highlights** warning in the editor's language status indicator identifies when diagnostics or their highlights are limited for performance reasons:

* **Diagnostic source limit:** Each extension diagnostic collection can provide up to 1,000 diagnostics per file. If a collection exceeds this limit, the warning indicates that some diagnostics are not shown.
* **Editor highlight limit:** The editor highlights up to 5,000 diagnostics per file across all sources. If this limit is exceeded, the warning indicates that only 5,000 diagnostics are highlighted.

If both limits are reached, the warning reports both conditions. Hover over the language status indicator in the Status Bar to view the details.

![Screenshot showing the language status bar diagnostic highlights addition](images/1_143/diagnostic-highlights.png)

## Enterprise

### Organization defaults without locking model choices

Your organization can set model, Auto tier, reasoning effort, and context defaults for new Copilot chats without locking your choices. You can change supported options per chat. Existing chats keep their available configuration.

The picker marks the **Org default**, and Settings explains when it overrides `setting(chat.defaultModel)`. Your saved preference applies again when the managed default is removed.

![Screenshot showing the model picker identifying the organization default and explaining that you can choose another model for the chat.](images/1_143/managed-model-default-picker.png)

![Screenshot showing the Chat: Default Model setting marked Managed by organization.](images/1_143/managed-model-default-settings.png)

For example, default new chats to Auto with the Intelligence tier in [enterprise-managed settings](https://docs.github.com/en/copilot/how-tos/administer-copilot/manage-for-enterprise/use-managed-settings/get-started), not user settings:

```json
{
    "model": "auto",
    "autoTier": "intelligence"
}
```

### Know why Local is disabled

When your organization requires the [Copilot harness](https://code.visualstudio.com/docs/agents/run/agent-harnesses), **Local** stays visible but disabled, with a briefcase icon and **Learn why** link.

![Screenshot showing Local disabled by policy in the harness picker, with a Learn why link explaining that the organization requires Copilot.](images/1_143/local-harness-disabled-by-policy.png)

Copilot is required to enforce nonempty managed `permissions.deny` rules or `sandbox.enabled: true`, unless the temporary override below applies. Other permission settings and an empty deny list do not trigger this requirement.

Administrators can explicitly prohibit Local through enterprise-managed settings:

```json
{
    "vscode": {
        "temporaryAllowLocalHarness": false,
        "temporaryDefaultToLocalHarness": false
    }
}
```

| Setting | Description |
| --- | --- |
| `vscode.temporaryAllowLocalHarness` | `false` prohibits Local, Claude, and Codex harnesses, overriding the temporary default below. `true` does not override other policies. |
| `vscode.temporaryDefaultToLocalHarness` | `true` keeps Local available and suppresses automatic Copilot routing, including deny-list and sandbox requirements. Explicit and remembered choices are preserved. |

When Copilot is required, opening unarchived Local chats moves them to Copilot. Editor inline chat and other Claude and Codex restrictions are unchanged.

> **Note:** These controls are temporary while Local is retired. Local cannot enforce runtime-only permission and sandbox controls. Do not enable the temporary Local override if you require those controls.

### Fewer interruptions while organization settings load

Copilot chats and model changes now wait for slow organization settings to load, with progress and a **Retry** option on failure. You can still select **Stop** while waiting. Organization restrictions apply before requests run.

### Fewer approval prompts for managed tools

[Assisted permissions](https://code.visualstudio.com/docs/agents/run/approvals#permission-levels) no longer prompt again for eligible managed tool requests they approve. One-time limits, managed denials, and sandbox restrictions still apply.
