## Agents

### Computer Use in Copilot harness sessions

**Setting**: `setting(chat.agentHost.computerUse.enabled)`

Some tasks happen in desktop apps rather than in your code or terminal. With Computer Use, the agent can see and control apps on your computer. Computer Use works in [Copilot harness](https://code.visualstudio.com/docs/agents/run/agent-harnesses) sessions that run on your own macOS or Windows machine.

When a task needs Computer Use, the agent asks you to allow turning it on, or you can run `/computer on`. Computer Use stays on for Copilot until you run `/computer off`.

### Session composer controls (Experimental)

**Settings**: `setting(sessions.chat.experimental.newSessionComposerLayout)`, `setting(sessions.chat.experimental.environmentPicker)`, `setting(sessions.chat.experimental.workspaceOptOut)`

Keep your prompt in view while choosing where and how an agent works. The new-session composer groups workspace, repository, and harness controls above the chat input in the Agents window and is enabled by default in VS Code 1.144 Stable.

This release adds these ways to configure a session without losing your draft:

* **Choose the environment first:** In the desktop Agents window, select **This Computer**, **Cloud**, an eligible remote host, or a supported Dev Container before choosing a workspace. Environment stays visible when session options are collapsed, and workspace and harness choices follow the selected environment. Local sessions retain the separate **Branch / New Worktree** isolation controls.
* **Chat without a project:** Enable `setting(sessions.chat.experimental.workspaceOptOut)` to reveal an **X** on workspace-picker hover or keyboard focus. Select it to start a workspace-less chat while preserving your prompt and attachments. The action is available only for harnesses and environments that support workspace-less chat.
* **Reduce clutter:** Select **Collapse to Icon** from any session picker's context menu. Each picker retains its tooltip and accessible name, and your choices persist across reloads and Settings Sync.
* **Use the keyboard:** From the focused new-session chat input, use `kb(sessions.focusNewSessionEnvironmentPicker)`, `kb(sessions.focusNewSessionBranchPicker)`, `kb(sessions.focusNewSessionWorktreePicker)`, or `kb(sessions.focusSessionSyncAction)` to reach available controls. Collapsed session options expand as needed. The Sync shortcut only moves focus. Press Enter to synchronize.

To hide the separate Environment picker, disable `setting(sessions.chat.experimental.environmentPicker)`. Environment choices remain available in the workspace and harness pickers. The experimental environment-order, local-isolation, and environment icon-only settings have been removed. Use the picker's **Collapse to Icon** action instead of an icon-only setting.

### Compare models in more projects

**Settings**: `setting(sessions.chat.compareAgents.enabled)`, `setting(sessions.chat.compareAgents.showPickerHint)`

[Model comparisons](https://code.visualstudio.com/docs/agents/run/compare-models) run the same prompt across multiple models so you can review their responses side by side. **Compare Models** is enabled by default in VS Code 1.144 Stable for eligible new sessions in the Agents window, so you no longer need to turn on a setting first. Explicit user settings and experiment overrides still apply.

You can compare models in more situations:

* **Explore ideas without a project:** Run independent attempts from a folderless **Chat**, without a Git repository, judge, or synthesizer.
* **Start with a local or empty repository:** A Git remote and an initial commit are no longer required. For repositories without commits, each isolated attempt starts from a snapshot of non-ignored working files without changing your source branch or index.
* **Open setup from the keyboard:** Press `kb(sessions.compareModels)` from an eligible chat input or model picker.
* **See where setup takes you:** Navigation buttons name their destination, such as **Configure Judge**, **Configure Attempts**, and **Configure Synthesis**, instead of using generic next and previous labels.

For an additional discovery entry point, enable `setting(sessions.chat.compareAgents.showPickerHint)` to show **Send Query to Multiple Models** at the bottom of the model picker. The hint disappears after you first open comparison setup, and the **Compare Models** toggle remains available. Model comparisons are not supported in Dev Containers.

### Worktree cleanup filters and low-disk notifications (Experimental)

**Setting**: `setting(chat.agentSessions.sessionStorageCleanupSuggestion.enabled)`

The previously introduced **Chat: Open Worktree Cleanup** helps you reclaim storage from agent session worktrees. This release adds more ways to find the worktrees you want to remove:

* **See worktrees from any time:** **Any time** is selected by default, so you can review recent worktrees as well as older ones.
* **Find worktrees by workspace:** Each row shows its workspace, and a workspace filter narrows the results. Changing the workspace filter clears the selection.

When cleanup suggestions are enabled and a local worktree's disk has less than 5 GB available, the Agents window offers **Open Worktree Cleanup** below the Sessions list regardless of worktree age or count. The action opens cleanup with **Any time** selected.

### Install Extension tool removed from the Local harness

The **Install Extension** (`#installExtension`) agent tool is no longer available in Local agent sessions. When you create a new workspace from chat, the agent no longer installs extensions. Instead, it adds the extensions the project needs to `.vscode/extensions.json`, so you can review and install them from the Extensions view. When you run a Python cell in a Jupyter notebook without the Jupyter extension, the kernel picker prompts you to install it.

If your custom agents or prompt files reference `#installExtension`, remove that reference. _[#343118](https://github.com/microsoft/vscode/issues/343118)_

### Run VS Code Command tool removed from the Local harness

The **Run VS Code Command** (`#runCommand`) agent tool is no longer available in Local agent sessions. Built-in workflows that relied on it now work without it. For example, when chat diagnoses network issues, it asks you to run **Developer: Chat Diagnostics** and share the report.

If your custom agents or prompt files reference `#runCommand`, remove that reference. _[#343125](https://github.com/microsoft/vscode/issues/343125)_


## Chat

### Voice conversations with session context (Experimental)

**Settings**: `setting(agents.voice.enabled)`, `setting(agents.voice.useBYOKVoiceModel)`, `setting(agents.voice.sessionAwareness)`

[Voice Mode](https://code.visualstudio.com/docs/configure/accessibility/voice) lets you discuss tasks aloud while the coding agent works. With an OpenAI live model and your own API key, you can ask questions such as 'Where were we?' or 'Which session needs input?' without starting a coding request.

The enabled-by-default `setting(agents.voice.sessionAwareness)` shares a bounded briefing of tracked sessions and recent active-chat context with OpenAI BYOK Voice Mode. It includes session titles, response summaries, pending prompt details, the selected model, and attachment names, but not attachment contents. Disable the setting and reconnect Voice Mode to restore input-only context. Hosted Voice Mode is unchanged.

GPT Live conversations also handle follow-ups and ongoing work more predictably:

* Clarifications from an idle conversation keep the original spoken request, question, and answer together when handed to the coding agent, instead of submitting only the latest answer.
* Single-question forms read the full question, and multi-question forms collect one numbered answer at a time.
* New spoken coding instructions during ongoing work are sent as steering rather than queued until the task finishes. Steering applies at the next opportunity supported by the provider and does not guarantee immediate interruption. Voice-only exchanges during ongoing work are not retained for later requests.
* Repeated starts avoid redundant model-discovery requests, while each connection still creates a fresh live session and checks credentials and policy.

### Localized voice approvals and clearer connection status (Experimental)

**Setting**: `setting(agents.voice.language)`

Respond to GPT Live tool confirmations with explicit approval or rejection phrases in any of Voice Mode's 25 speech-recognition languages, with English phrases available as a fallback. Question forms accept displayed localized choice labels, choice numbers, or free text where permitted. Ambiguous approval replies still require an explicit answer or the chat controls.

Question text comes from the coding agent. Changing the voice language does not translate it. Localized choice replies work when the agent supplies localized choices. Shorthand commands such as 'skip' and 'other' remain English-only.

Voice Mode uses a consistent blue connection indicator, including while muted. Its hover identifies an active OpenAI GPT Live connection, and the GPT Live provider notice appears only on the first successful connection per profile rather than on every reconnect.

## Editor Experience

### Issue Reporter

**Settings**: `setting(issueReporter.wizard.enabled)`, `setting(issueReporter.wizard.openLocation)`, `setting(issueReporter.additionalRepositories)`

Issues with clear steps, screenshots, and logs are faster for us to reproduce and fix. The [new issue reporter](https://code.visualstudio.com/updates/v1_122#_improved-issue-reporting-flow), which you turn on with `setting(issueReporter.wizard.enabled)`, makes it easier for you to create high quality issues. You can capture screenshots and screen recordings without leaving VS Code, from the capture bar or with kb(workbench.action.issueReporter.captureScreenshot) and kb(workbench.action.issueReporter.toggleRecording).

This release makes these changes to the new issue reporter:

* The form fits on a single page instead of three steps.
* Attach other files that help us debug your issue, such as log files or zip archives. You can also paste or drop images and videos into the form.
* The reporter opens in its own window. To open it in an editor tab instead, set `setting(issueReporter.wizard.openLocation)` to `editor`.
* To file issues in other GitHub repositories, for example your team's own tracker, add them to `setting(issueReporter.additionalRepositories)` in `owner/repo` format. Then pick the repository in the form.

## Extension Authoring

### Publish extensions with OIDC and Trusted Publishing

You can now publish extensions to the Visual Studio Marketplace from GitHub Actions without storing a Personal Access Token (PAT) as a repository secret. The `vsce publish --oidc` command requests a short-lived OpenID Connect (OIDC) token from GitHub Actions and exchanges it for a temporary Marketplace credential that is valid for up to 15 minutes. If the token exchange fails, `vsce` doesn't fall back to a PAT.

To get started, create a Trusted Publishing policy for your repository and workflow in the Visual Studio Marketplace publisher management page, grant the publishing job the `id-token: write` permission, and run `vsce publish --oidc` in your workflow. Use a version of `@vscode/vsce` that supports OIDC, such as `4.0.2` or later.

Trusted Publishing is currently supported for GitHub Actions only. For Azure Pipelines, continue to use Microsoft Entra ID with a service connection. As global PATs in Azure DevOps are retired on December 1, 2026, we recommend that you move your extension publishing to one of these secure methods.

Learn more about [publishing extensions with vsce](https://code.visualstudio.com/api/working-with-extensions/publishing-extension#publish-with-github-actions-and-trusted-publishing).

Learn more about [Trusted Publishing in the Visual Studio Marketplace blog post](https://aka.ms/vsm/trustedpublishing/blogpost).
