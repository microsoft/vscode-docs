## Agents

### Computer Use in Copilot harness sessions

**Setting**: `setting(chat.agentHost.computerUse.enabled)`

Some tasks happen in desktop apps rather than in your code or terminal. With Computer Use, the agent can see and control apps on your computer. Computer Use works in [Copilot harness](https://code.visualstudio.com/docs/agents/run/agent-harnesses) sessions that run on your own macOS or Windows machine.

When a task needs Computer Use, the agent asks you to allow turning it on, or you can run `/computer on`. Computer Use stays on for Copilot until you run `/computer off`.

### Install Extension tool removed from the Local harness

The **Install Extension** (`#installExtension`) agent tool is no longer available in Local agent sessions. When you create a new workspace from chat, the agent no longer installs extensions. Instead, it adds the extensions the project needs to `.vscode/extensions.json`, so you can review and install them from the Extensions view. When you run a Python cell in a Jupyter notebook without the Jupyter extension, the kernel picker prompts you to install it.

If your custom agents or prompt files reference `#installExtension`, remove that reference. _[#343118](https://github.com/microsoft/vscode/issues/343118)_

### Run VS Code Command tool removed from the Local harness

The **Run VS Code Command** (`#runCommand`) agent tool is no longer available in Local agent sessions. Built-in workflows that relied on it now work without it. For example, when chat diagnoses network issues, it asks you to run **Developer: Chat Diagnostics** and share the report.

If your custom agents or prompt files reference `#runCommand`, remove that reference. _[#343125](https://github.com/microsoft/vscode/issues/343125)_

## Editor Experience

### Issue Reporter

**Settings**: `setting(issueReporter.wizard.enabled)`, `setting(issueReporter.wizard.openLocation)`, `setting(issueReporter.additionalRepositories)`

Issues with clear steps, screenshots, and logs are faster for us to reproduce and fix. The [new issue reporter](https://code.visualstudio.com/updates/v1_122#_improved-issue-reporting-flow), which you turn on with `setting(issueReporter.wizard.enabled)`, makes it easier for you to create high quality issues. You can capture screenshots and screen recordings without leaving VS Code, from the capture bar or with kb(workbench.action.issueReporter.captureScreenshot) and kb(workbench.action.issueReporter.toggleRecording).

This release makes these changes to the new issue reporter:

* The form fits on a single page instead of three steps.
* Attach other files that help us debug your issue, such as log files or zip archives. You can also paste or drop images and videos into the form.
* The reporter opens in its own window. To open it in an editor tab instead, set `setting(issueReporter.wizard.openLocation)` to `editor`.
* To file issues in other GitHub repositories, for example your team's own tracker, add them to `setting(issueReporter.additionalRepositories)` in `owner/repo` format. Then pick the repository in the form.
