## October 2, 2026

### Compare multiple agent attempts (Experimental)

Compare several implementations of the same task without manually coordinating separate sessions. In a Git repository with at least one commit, enable `setting(sessions.chat.compareAgents.enabled)`, open the agent picker in a new session, and select **Run and Compare Agents**. You can configure two or more agent and model combinations, and choose the agent and model that judges the results.

Each attempt receives the same prompt and context, and runs in a separate, isolated worktree. After the attempts finish, the Judge reviews their changes and available validation evidence, and recommends an implementation. You can inspect any attempt, select **Focus Winning Session**, or select **Synthesize Attempts** to create a new implementation from the results.

The recommendation is advisory. VS Code does not automatically apply an attempt or delete its worktree. _[#335085: Agents window: Compare multiple implementation attempts](https://github.com/microsoft/vscode/issues/335085)_

### Simplified new-session controls (Experimental)

The experimental new-session composer keeps your prompt at the center while making session choices easier to review. With `setting(sessions.chat.experimental.newSessionComposerLayout)` and `setting(sessions.chat.unifiedWorkspacePicker.enabled)` enabled, workspace, repository, and harness controls appear in a collapsible **Session Options** tray above the chat input.

Collapse the tray to reduce visual clutter without changing your selections. The composer remembers your choice, adapts labels as the window narrows, and keeps the options expanded when screen reader optimized mode is active. When you use a custom chat background, the tray has an opaque surface to keep its controls readable. _[#338543: Progressively disclose advanced new-session options](https://github.com/microsoft/vscode/issues/338543), [#339111: Keep the experimental composer opaque over custom backgrounds](https://github.com/microsoft/vscode/issues/339111)_

### Add Context opens beside your prompt

The **Add Context** picker now opens next to the button that invoked it and closes when you select the button again. This keeps the picker visually connected to the chat input in the editor and Agents windows.

As a separate experiment, enable `setting(sessions.chat.experimental.agentsPickerInAttachContextMenu)` to initially place the **Agent** picker in **Add Context**. After you select an agent, its picker returns to the chat toolbar. _[#338928: Anchor Add Context picker to its chat input button](https://github.com/microsoft/vscode/issues/338928), [#338936: Move the Agents Window agent picker into Add Context](https://github.com/microsoft/vscode/issues/338936)_

### Customize new-session welcome messages (Experimental)

Enable `setting(sessions.chat.experimental.welcomePhrases)` and personalize the welcome heading above the new-session composer with `setting(sessions.chat.experimental.welcomeMessages)`. Add your phrases to the defaults or replace the default phrases, and use the `{name}` placeholder to position your welcome name anywhere in a phrase.

Select **Customize Welcome Message** beside the heading to change your name or open the phrase setting. You can also right-click the heading and select **Hide Welcome Message** to turn welcome phrases off. _[#339038: Let users customize new-session welcome phrases](https://github.com/microsoft/vscode/issues/339038), [#339134: Enable context menu hide of welcome phrases](https://github.com/microsoft/vscode/issues/339134)_

## September 29, 2026

### Reclaim storage from inactive worktrees

Run **Chat: Open Worktree Cleanup** to see how much disk space inactive agent session worktrees use and remove the ones you no longer need. Filter sessions by how long they have been inactive, review each worktree's size, and select the worktrees to clean up.

Cleaning up marks the selected sessions as done and deletes their worktrees. You can restore a session later to recreate its worktree. Active, running, needs-input, and pinned sessions are protected from cleanup. _[#338039: Add manual cleanup command for Agents Window worktrees](https://github.com/microsoft/vscode/issues/338039)_
